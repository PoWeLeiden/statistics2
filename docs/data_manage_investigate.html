1  Investigating Your Data and Data Cleaning

You will learn how to analyze data using linear and logistic regression models in the chapters to come. However, it is a rare day where a researcher can simply download a dataset and jump directly into the analyses that they wish to perform. Instead, we often need to take some first steps to prepare our data for analysis, a process referred to as “data cleaning”, “cleaning our data”, or “data management”. Data cleaning requires us to know something both about the types of analysis that we want to perform as well as the nature of the variables present in our dataset. This information is often provided in a separate codebook for the dataset (or in Exercise/Assignment instructions!). However, we can also learn some important facts from the dataset itself.

In Section 1.1, we will go over some commands you can use to familiarize yourself with your data so that you can accurately identify the steps you need to take in order to clean your data and hence analyze it. In Chapter 2, meanwhile, we will go into greater depth regarding a specific data management task of particular importance in Statistics II: creating and manipulating factor variables.

1.1 Learning about your data

The first thing we do when analyzing data in R is load the libraries needed for our analyses before importing our data. these libraries are already installed on university computers but must first be loaded before use. You can use the command in Appendix B to install these packages on your personal computer.1 We will use a dataset that contains information about the political and economic characteristics of countries from across the world.

#Packages
library(rio)          #loading data
library(sjPlot)       #for obtaining overviews of data objects
library(tidyverse)    #data manipulation and plotting

#Data
demdata <- import("demdata.rds") |> 
  as_tibble()

We have loaded a data file…but what’s inside it? We can get to know our data better both by using commands that enable us to obtain an overview of the dataset as a whole as well as via commands that let us investigate the characteristics of specific variables.

view_df() creates output with the following columns:

  • ID: The column number of the variable
  • Name: The variable name
  • Label: The variable label ($label) if there is one stored in metadata. This is a short description of what the variable is supposed to measure.
  • Values: If the variable is a continuous variable, then this will likely show “range: X-X”. For instance, the v2x_libdem variable ranges from 0 to 0.9. For instance, we see that a 1 on TypeEcon2006 refers to a country with “High GDP”, while a 2 refers to “Medium GDP”. If a variable is a factor variable (e.g., TYPEDEMO1984), then the labels associated with each level of the factor are provided here and there will be no entries in the Values column.

1.1.2 Investigating variables

R datasets may contain variables that vary in their class (or type). Common variable classes include:

  • Numeric variables where the data are numbers including ones that include decimals
  • Integer variables where the numeric data is limited to whole numbers
  • Character variables where the data is a string of letters (e.g., “Australia”)
  • Factor variables representing categorical (nominal or ordered) variables
  • Logical variables where the only values are TRUE or FALSE
  • Date variables (e.g., “2026-05-03”)

Learning a variable’s class can be an important first step in the data cleaning process as it can help us understand the types of actions (if any!) that we need to perform to prepare the variable for inclusion in our analyses.

We can use two tools to learn about a variable’s class. First, we can use the class() function that you learned about in Statistics I (link) to directly obtain this information. Second, we can use the attributes() function to investigate whether there is any metadata associated with the variable in our dataset. Not all datasets, or variables within datasets, will contain metadata but some do and they can tell us important information about the data before us. This metadata may include:

  • $label: A short description of what the variable is supposed to measure
  • $labels : If the variable is numeric and only takes on a few values, then there may be labels for each value telling you what each value represents
  • $levels : If the variable is a factor variable, then this would tell you about the levels of the factor. We discuss this in greater depth in Chapter 2
  • $class : This indicates the class of the variable. However, this option is not always shown in the output of attributes() as it needs to be explicitly stored in the variable’s metadata. This will be the case for factor variables, but not necessarily for other types of variable.

Conveniently, our dataset has a variety of different variable types that vary in whether they possess metadata or not.

  • v2x_libdem is a numeric variable but one without any metadata associated with it as seen by the NULL output after the attributes() command. If we wanted to know more about this variable then we would need to turn to a codebook (or, closely read exercise/assignment instructions).
  • HDI2005 is also a numeric variable but here we have a handy $label entry that tells us what this variable measures: a country’s Human Development Index, or HDI. The label also implies that the data is from the year 2005, on a 0-100 pt scale, and is sourced from the UNCDP in 2007.3
  • TYPEDEMO1984 is a factor variable. Observations can have either of two potential (non-NA) values: “Autocracies” and “Democracies”. We do not have a variable label here to tell us what the variable is about, but we can perhaps deduce from its name and these levels that this data records the type of regime a country had in the year 1984.
  • TypeEcon2006 is a numeric variable that indicates something about the country’s economy. This measurement appears to come from the World Bank and refers to the country’s economic status in the year 2006 (per the variable name). This variable has a $labels area that tells us that non-NA observations can take on one of four numeric values: 1, 2, 3, or 4. Importantly, one of those values (4) represents a “Missing” category, i.e., observations with a 4 on this variable could not be classified as having High/Medium/Low GDP due to missing economic data.

In practice, we would follow up these steps by investigating the variables using tools such as summary() , mean(), table(), and so on, to get a further sense of the variables before us. For instance:

# summary() to get an overview of continuous variables
summary(demdata$HDI2005)
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max.    NA's 
 0.3360  0.5800  0.7640  0.7240  0.8628  0.9680      21 
# table() to get an overview of categorical/discrete variables
table(demdata$TypeEcon2006, useNA = "always") 

   1    2    3    4 <NA> 
  30   57   78   14    0

In this case, summary() tells us both about the distribution of the distribution of the HDI2005 variable and also that there exist 21 observations with NA (or missing) values.4 Meanwhile, we can also see that 14 observations have a value of 4 (representing a “Data Not Available” category”) on the TypeEcon2006 variable.

We can use what we just learned to understand the steps we need to take, or not take, in cleaning these variables for analysis. The v2x_libdem and HDI2005 variables are both numeric variables where “missing” is simply represented by NA in our dataset. These variables are likely ready for analysis as is.5 On the other hand, missing data is encoded as a value of 4 for the TypeEcon2006 variable. In these types of situations we will want to convert these values into an NA value to make the variable ready for use. Finally, we include binary variables like TYPEDEMO1984 in our regression analyses by converting them to a factor variable…but this is already done, so again we can likely proceed with the variable as is (unless we want to relevel it to make our analyses clearer as discussed in Section 2.2).

1.2 Managing your data and variables

Learning more about your data may reveal the need to perform a variety of different data management tasks prior to conducting your final analysis. This may involve some or all of the following steps, many of which were introduced in Statistics I (see links to the Statistics I R book in parentheses):

  • Filtering out unnecessary data using filter() (link)
  • Correctly marking missing data as NA in our dataset with tools such as na_if(), ifelse(), or case_when() (link)
  • Recoding variables with recode() (link 1; link 2)
  • Creating new variables via mutate() (link)
  • Converting binary/categorical variables into factor variables (covered in Chapter 2)
  • Creating new datasets by joining two or more together with left_join() (link)

Below, we give just a few examples to refresh the most important syntax.

1.2.1 Filtering data

# ex1: Filter to keep only democracies in the dataset
demdata_democracies <- demdata |> 
  filter(TYPEDEMO1984 == "Democracies")

# ex2: Filter to keep only observations with non-missing data on these 2 variables
demdata_complete <- demdata |> 
  filter(complete.cases(TypeEcon2006, HDI2005))

1.2.2 Converting numeric missing value codes to NA

# ex1: na_if
demdata <- demdata |> 
  mutate(TypeEcon2006_na = na_if(TypeEcon2006, 4))

# Check your work!

demdata <- demdata |>
